# 5. 实验协议

## 5.1 数据集顺序

开发只先做：

```text
PEMS08
```

PEMS08 完整模型和核心实验没有闭环前，不并行调试其它数据集。

```text
PEMS03

PEMS07
METR-LA
PEMS-BAY
```

## 5.2 12 → 12

```text
history [B,12,N,1]
prediction [B,12,N,1]
```

主实验 traffic-only。

## 5.3 Split

只使用官方/预切分 train / val / test。禁止 concatenate 后重新 split。每个 split 独立滑窗，禁止跨 split。

PEMS08 expected windows：

```text
train 10690
val    3548
test   3549
```

Phase 0 必须 exact test。

## 5.4 Scaling / mask

使用 train-only global scalar Z-score：

```text
mu  = mean(raw train traffic)
sigma = std(raw train traffic, ddof=0)
```

raw null validity 在 normalization 前定义：

```text
~np.isclose(x, 0, atol=5e-5)
```

0 值参与 scaler statistics。

invalid normalized target/input position 按冻结协议处理，metric 必须与 BasicTS golden semantics 对齐。

## 5.5 Metrics

训练：

```text
normalized masked MAE
```

Validation / formal test：

```text
inverse transform
raw-scale MAE / RMSE / MAPE
12 horizon metrics
```

聚合：

```text
MAE  = total SAE / total valid
RMSE = sqrt(total SSE / total valid)
```

禁止 average(batch RMSE)。

Persistence baseline：latest traffic 重复到 12 horizons，使用相同 raw-scale validation protocol。

# 6. Formal Training Protocol

第一版固定：

```text
Optimizer: AdamW
lr=1e-3
betas=(0.9,0.999)
eps=1e-8
weight_decay=1e-4 for ndim>=2, else 0
grad_clip=5.0
batch_size=64
precision=FP32
AMP=false
DDP=false
```

Cosine schedule，最多 100 epochs：

\[
lr_e
=
10^{-5}
+0.5(10^{-3}-10^{-5})
(1+\cos(\pi e/99))
\]

其中 `epoch_index=0..99`。

Early stopping：

```text
patience=15
min_delta=0
monitor raw-scale average validation MAE
```

Family hard Top-p warm-up：

```text
displayed epoch 1..5: OFF
displayed epoch 6+:   ON
```

即 `epoch_index 0..4` 不应用 family hard Top-p；从 `epoch_index=5` 开始应用。

warm-up 时 train/val 使用相同开关。

warm-up validation：

```text
log only
not eligible for best checkpoint
not eligible for early-stopping patience
```

第 6 displayed epoch 起才进入正式 best/patience 竞争。

主 loss：

```text
masked prediction MAE only
```

不实现 Router balance loss。

Development：

```text
train + validation
不得读取 test metric
```

Final：

```text
frozen config
train/val selection
reload best checkpoint
test exactly once per completed run/seed
```

Test 结果不得反向修改设计、阈值、hyperparameter 或 checkpoint selection。

第一版 checkpoint 合同只覆盖 `best`、`last`、strict reload 与正式 test 前 best reload。**不实现 training resume**；不得提前构建 RNG/sampler/state 恢复框架。

# 8. Numerical Safety 与 Hot Path

数学合同：

```text
valid NaN/Inf -> hard failure
loss NaN/Inf  -> hard failure
gradient NaN/Inf -> hard failure
```

但 production hot path 禁止为了“安全”每 batch 大量 host synchronization。

禁止 hot-loop：

```text
Python bool(CUDA tensor)
大量 tensor.item()
大量 tensor.cpu()
masked_select + host finite check
每个 parameter 每 batch host-side finite scan
```

正确方式：

```text
unit/golden tests
strict debug path
device-side/async assertion where suitable
controlled synchronization/failure boundary
```

禁止 `nan_to_num` 洗掉 valid logits 的错误。

Debug correctness path 与 production performance path 必须分开。

# 19. PEMS08 正式研究证据顺序

代码完整后，不要立刻扩六数据集。先在 PEMS08 完成核心假设验证。

正式研究顺序：

1. full HiDFilter 多 seed 稳定性；
2. Hierarchical vs Flat；
3. Sensor-Lag vs Sensor-only；
4. Multi-Lag vs Single-Lag；
5. Top-p vs matched-cardinality Top-K；
6. Family Evidence Router vs target-only；
7. no-prior；
8. family removal（Self / Physical / Semantic）；
9. \(\rho\) sensitivity：建议少量 `0.7 / 0.8 / 0.9 / 1.0`；
10. candidate source pool sensitivity：建议 `K=4 / 8 / 12 / 16`，主模型固定 8。

关键原则：

```text
一次只改变一个核心因素
所有 ablation 从头训练
test 不参与 ablation 选择
Top-p vs Top-K 尽量匹配平均 selected cardinality
```

如果 H2（Sensor-Lag）和 H3（Multi-Lag）都长期失败，应重新审视核心假设，而不是继续堆模块。

```text
protocol

```
